## §0 最小记忆集（四个锚点）

1. **指标要分层**：过程(工具正确率/步数/成本延迟) · 结果(成功率/**Pass@k vs Pass^k**) · 安全(一票否决) · 鲁棒性。
2. **开放任务靠 LLM-as-Judge**，但要用**结构化 Rubric**（四准则 + 一票否决），并**先用金标集校准**（否则 judge 只是"另一个模型的意见"）。
3. **分差 < 噪声带宽就别切换**：小评估集 + 模型不确定性 → 3% 的分差可能是噪声。多跑几次 + 配对分析。
4. **可观测性是评估的数据地基**，而且能**回流成评估资产**（生产失败案例 → 脱敏 → 新回归用例）。

## §2 指标词典（该度量哪些维度）

**过程指标（白盒，看 Agent 怎么做到的）**：
- **行动合法率**：调用存在的工具、参数类型对、不越权。
- **工具调用正确率**（JD 点名）：参数语义合理（搜索词准、路径对）。
- **路径效率**：步数 / 冗余动作 / **回退次数**（偶尔回退正常，频繁=前瞻规划不足）。需人类/启发式基线定义"合理步数"。
- **成本与延迟**（JD 点名）：请求数、token（分输入/输出、算 KV Cache 复用）、墙钟时间（模型+工具+网络），**追踪时间分布定位瓶颈**（= 你 Langfuse 看到的）。

**结果指标**：
- **任务成功率**（JD 点名，最硬）：可层次化（核心目标必达 / 次要目标影响评分）。
- **⭐ Pass@k vs Pass^k vs Best@k**（最易混，面试爱考）：
  - **Pass@k** = k 次**至少一次**成功 → "能不能做到"（能力上限）
  - **Pass^k** = k 次**全部**成功 → "稳不稳定"（可靠性）
  - 具体感受：单次 60% → **Pass@5 ≈ 99%**，**Pass^5 ≈ 7.8%**。混用会误判！
  - 回归测试用 **Pass^k**（Pass@k 会掩盖不稳定）；探索能力上限用 **Pass@k/Best@k**。

**安全与合规指标**：触发敏感操作/数据外泄/违规内容 → **零容忍，一票否决**（一次严重违规否决整体，不因其他维度优秀豁免）。

**鲁棒性**：随机种子敏感性、UI 变化适应、API 抖动容忍、长时记忆干扰。

**⭐ 轨迹 vs 结果双重覆盖**（L5「看动作不看话术」的体系化）：
- Agent 说"订票完成"= 轨迹；数据库真有订单 = 结果。
- 只看轨迹漏"说了没做到"；只看结果看不出中间走歪。**两类都要测。**

## §3 LLM-as-a-Judge（你做过 judge，这课教怎么做好）

**为什么要**：开放任务（客服对话/报告）无标准答案，人工评估贵。让 LLM 按 Rubric 打分 = 自动化 + 专业判断的平衡。

**已知局限**：
- **长度偏差**（最典型）：倾向给**更长**的回复高分,哪怕不更正确。防范三招:Rubric 显式惩罚冗长/规定长度上限 · 配对比较先把两者长度控到相近 · 定期审计"分数-长度相关性"。
- 相同输入多次评判有波动。

**⭐ Rubric 四准则（Scale AI "Rubrics as Rewards"）**：
1. **基于专家指导**——反映领域知识（医疗要含诊断标准），不能只抓语言流畅度。
2. **全面覆盖 + 明确陷阱(Pitfall)**——不只定义正面标准，还要列高风险常见错误。
3. **标准重要性权重 + 一票否决(Veto)**——必要/重要/可选/陷阱四级；**幻觉/安全违规 = 否决维度,触发即总分归零**（防关键词堆砌作弊）。
4. **自包含可验证**——避免"展示了深刻理解"这种抽象；改成"引用≥2个权威理论并解释如何支持结论"。

**防奖励作弊(Reward Hacking)**：明确惩罚幻觉、讨好用户、关键词堆砌、回避棘手问题。Rubric 是**迭代产物**（收集评价者分歧逐步完善）。

**Rubric 长这样**（多维度 + 四档 + veto + edge_cases，YAML）：
```yaml
dimensions:
  - name: 事实正确性
    weight: essential
    scoring: {4_优秀: "准确回答且关联到...", 1_不及格: "错误或答不知道"}
  - name: 幻觉检测
    weight: veto          # 一票否决:触发即总分归零
    scoring: {pass: "所有信息可溯源", fail: "编造了不存在的信息"}
edge_cases: ["有多个女儿时应追问是哪个", "Dr.Chen 与 陈医生 应识别为同一人"]
```

**⭐ 评判者校准（放量前必做）**：先建**金标集**(100-200 人工标注案例) → 测 judge 与人类的一致率(**Cohen's kappa**,剔除随机猜中成分) → **kappa > 0.7** 才放量。**没这一步,judge 分数只是"另一个模型的意见",不是人类判断的可靠代理。** judge/Rubric 每次更新都要重新校准。

**同源模型问题 → 多源评判**：judge 和被评是同一模型有盲区（回扣你 L11 的判据 + reflect 同模型自审）；用多个独立评判者 + 加权/一致性检查，严重分歧标记人工。

## §4 统计显著性（别被噪声骗，JD/面试硬点）

- **二项标准误** SE ≈ √(p(1-p)/n)。例：100 用例、成功率 70% → SE≈4.6% → 95%CI ≈ **70%±9pp**。
- **"新模型 73% vs 旧 70%"这 3pp 完全在噪声内** → 据此切换≈掷硬币。两个成功率独立相减,差值 SE≈单个的 √2 倍(≈6.5%)。
- **多次运行取均值**：同模型同数据两次结果都会漂（温度/工具波动/时序）→ 每配置跑 **3-5 次不同种子**,报均值+波动。
- **配对分析(McNemar)**：同一批任务上比两配置,**逐题看胜负、只看结果不同的用例** → 扣除"题目难易"共同噪声,比独立相减灵敏得多。
- **多重比较陷阱**：6 个假设并行,"至少一个假阳性"概率 = 1−0.95⁶ ≈ **26%**。应对:收紧阈值(Bonferroni) 或对正向结论独立复跑。
- **实用原则：分差 < 噪声带宽 → 不切换**。若改进预期只有 2-3pp 而评估集只有几十条 → **先扩评估集,别再迭代 Agent**（这套评估根本分辨不出这点改进）。

## §5 可观测性 = 评估的数据地基（你刚做的 Langfuse）

- **Trace / span 树**（借自分布式系统）：一次执行=一条 trace,每个 LLM/工具/检索调用=一个 span,父子构成执行树。标准:**OpenTelemetry**(通用)+ **OpenInference**(LLM 语义约定)。采标准协议 = 采集与分析解耦,不被单一平台锁定。
- 平台:Langfuse / LangSmith / Arize Phoenix——把可观测性+评估+优化整合成闭环。**异步批量采集,不影响 Agent 延迟**（你代码里 flush 就是这个）。
- **⭐ 可观测性回流成评估资产**（最实用的闭环）：生产轨迹筛失败/可疑案例 → **脱敏** → 沉淀为评估集新用例/回归测试。**评估集从静态集合变成随产品演化的活资产**——今天线上的失败,明天就成守底线的回归用例。这就是**可观测性 ↔ 评估**的接口。
