# L7 讲义:RAG 与向量数据库

> JD 权重 **8/10,阶段二最高频,面试必问**。也是学习者绕了整门课的问题:
> L1 task A"模糊处理"、L3"按需检索工具"、L5 Q5"取哪几条最相关"、L6"外置"策略 —— 全指向 RAG。

## 1. 为什么需要 RAG:LLM 的三个先天缺陷
| 缺陷 | 例子 | RAG 怎么救 |
|---|---|---|
| 知识冻结(训练截止) | "你们上周改的退货政策" | 从最新文档检索 |
| 不知道私有数据 | 公司 10 万商品、内部 FAQ | 把私有库变可检索 |
| 塞不进去(L6 的账) | 几百万字塞不进上下文 | 只检索相关几段 |

> **RAG = 回答前先去外部知识库"查资料",把相关内容塞进上下文再作答。** 开卷考试:不用背,翻书找相关页。

## 2. 心智模型:两个阶段(全课最重要)
```
【A 离线建索引】平时做一次,把知识库变"可检索"
  文档 → ①切块 chunking → ②每块算 embedding → ③存进向量数据库
【B 在线检索生成】用户每次提问做
  问题 → ④问题算 embedding → ⑤向量库找最相似 top-k 块 → ⑥塞进 prompt → ⑦LLM 基于它生成
```
A = 建图书馆+编索引(慢/离线/一次);B = 带问题去书架抽相关几本(快/在线/每次查询)。

## 3. 核心机制:embedding = 文本变"语义坐标"
一个模型把文本变成定长向量,关键性质:**语义相近 → 向量相近**。
- "怎么退货" 与 "退款流程是什么" 向量挨得近;与"今天天气"离得远。
- 这就是 L1 说的"模糊处理":字面不同、语义相近也能检索到。**关键词匹配做不到,embedding 能。**

## 4. 检索:相似度 + top-k
- 余弦相似度(cosine)量两向量多近(越接近 1 越像)。
- 取 top-k(如 k=3)最相似的块,不是全给(L6 预算:塞太多既贵又稀释)。
- 向量数据库(chroma/faiss/milvus)专干此事:存海量向量,用索引(HNSW)毫秒级找 top-k。

## 5. chunking:切块 —— RAG 成败常在这(最被低估)
- 切太大 → embedding 抓不住重点、检索不准、占 token。
- 切太小 → 上下文断裂、检索到半句没头没尾。
- **切在语义边界(段落/小标题)** 远好于"每 500 字硬切"。
> embedding/检索再好,切块坏了 RAG 就废。"RAG 效果差怎么排查"→ 先查 chunking。

## 6. grounding:检索到 ≠ 模型会用(回扣 L6)
把检索块塞进 prompt 后,必须约束:"**只根据下面资料回答,没有就说不知道**"。
否则模型无视检索、凭记忆瞎编(RAG 最致命的幻觉)。
= Prompt 工程:检索把书翻到对的页,grounding 逼模型照着念别自由发挥。

## 7. RAG 难在哪(埋深水区,后续/capstone 回扣)
- 召回差:该检索到的没检索到(chunking/embedding 不匹配中文/query 改写)
- 精排:检索到一堆,哪几个真相关(rerank 重排序模型)
- 评估:RAG 效果怎么量化(命中率/忠实度)→ L12 评估
- 混合检索:向量 + 关键词(BM25)结合,各补短板

## 8. 作业(见 homework/)
从零搭一个最小可用 RAG:文档→切块→embedding→向量检索 top-k→grounding 生成。
用电商 FAQ/退货政策做知识库,验证"字面不同、语义相近"也能答对。
(embedding 方案与向量库选型开工时定 —— 注意端点无 embedding API,大概率用本地模型。)
